# 2026-10-04

## Windows support

- Command transport: a named pipe (`\\.\pipe\<runtime folder name>`) instead of a Unix socket; the
  same net API on both sides.
- The command on PATH: `more-space.cmd` (setlocal, ELECTRON_RUN_AS_NODE=1, `%*`, exit code passed on),
  which PowerShell and cmd both run with no execution policy involved.
- Terminal shell: pwsh.exe when on PATH, else powershell.exe, `-NoLogo`. Windows spells the variable
  `Path`: the instance's bin folder is prepended under the existing spelling, never a second key.
- Batch syntax shown to agents follows the platform (core/commands/batch.ts): a PowerShell here-string
  piped to `more-space -` on Windows, a heredoc elsewhere.
- Window: titleBarStyle hidden + titleBarOverlay (chrome color) on Windows; the page marks
  `data-platform` and the title bar leaves room on the right for the controls.
- Build script root used URL.pathname ("/D:/…" on Windows) → fileURLToPath.
- Packaging: NSIS installer (not one-click, directory choosable) + zip, x64, unsigned. CI and Release
  run on windows-latest too. Release can be run by hand: builds installers on all three systems and
  attaches them to the run as artifacts, without a release.
- tests/command-line.test.ts runs the real path end to end: generated command (sh, or .cmd through
  PowerShell), thin client, socket or pipe, board, and back, including a batch and a usage error.
- Terminal reactions were too loud while output streamed (working ↔ idle switches each spoke). Now only "Done" and "Your turn" speak; working is quiet, and settling back to rest is always quiet. Live check: 0 sounds over 4s of output, one voice on Done, none on settling.
- "Done" came on every 2.5s pause an agent takes between steps. Now it waits for 10s of quiet (Board.timing.doneAfter) and only follows work that lasted ≥5s (minWork); output within the gap continues the same work, and the character keeps looking busy through it. Live: bursts with a 4s pause gave no sound; Done once, 10s after the end.
- Windows packaging hung ~30 min converting icon.png to .ico (electron-builder's icon tool under Bun on Windows). bun run icon now writes assets/icon/icon.ico itself (PNG entries 16–256), packaging uses it; workflows got timeouts (release 20 min, CI 10).

## Codex could not find the command

- Cause: Codex runs commands through a shared background server (`codex app-server --managed-daemon`),
  started once and reused by every session. It had been started from a More Space terminal hours
  earlier, so it kept that instance's environment: a random runtime bin folder deleted since, and a
  dead socket. Every later Codex session ran commands there. Plain `codex exec` worked.
- Fix: the command now lives in a fixed folder, `<userData>/bin`, and each window registers itself in
  `<userData>/instances/<pid>.json` (socket, project), removed on quit. The command script sets
  MORE_SPACE_INSTANCES; the client tries the socket from the environment, then live windows whose
  project holds the (real) working folder, deepest first, or the only open window. A long-lived
  process started from any More Space terminal (Codex's server, tmux) keeps working across windows
  and restarts. One started outside More Space still cannot see it: README explains restarting it.
- Verified with real Codex: a stale socket in the environment, the fixed folder on PATH → found,
  and the line reached the board. The end-to-end test covers a stale socket with two open windows.

## The voice is for when the user is needed

- Avatar.quiet became Avatar.voice: "attention" ("Done", "Your turn"), "agent" (the agent set the
  mood), or none (working, file changes, settling back). The window speaks for "attention" always, for
  "agent" only with the new setting voiceMoods (settings.json, default off), toggled by "Speak on every
  mood" in the character gallery. Question bells are unchanged.
- A live check seemed to show the option not working: the user had switched to Anime Hero meanwhile,
  so the Cowboy moods the test sent were refused (output was discarded). Lesson: read command output
  in tests, and check the current character first. With its own moods: on → voice, off → silence.

## First release

- v0.1.0 published: https://github.com/zohayrslileh/more-space/releases/tag/v0.1.0 (tag push → three builds → draft → notes with a download table → published as latest). Intel macOS files carry no arch suffix (More-Space-0.1.0.dmg), Apple silicon ones say arm64.
- macOS 0.1.0 download said "damaged": identity null left it unsigned, which Apple silicon refuses for downloads. Now an ad-hoc signature (identity "-") with hardenedRuntime off (ad-hoc + hardened runtime blocks the native terminal library). Verified locally: codesign valid (adhoc), packaged app opens, its terminal runs more-space. README: Open Anyway in Privacy & Security for recent macOS; xattr for 0.1.0.
- 0.1.1 published (ad-hoc signed macOS; dmg from the release verified: adhoc, valid). publishAutoUpdate false + dmg writeUpdateInfo false + nsis differentialPackage false still left zip blockmaps; deleted by hand, and the macOS zip target dropped (dmg only). Update files removed from 0.1.0 too.
